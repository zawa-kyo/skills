# Distill Japanese Edits

人手による日本語修正から、再利用可能な書き方の知見を抽出し、ローカルの `revise-japanese-writing` スキルへ根拠付きで反映する。

## 目的

実際の人間による修正から学びつつ、`writing/revise-japanese-writing/` を改善する。
その際、1 つの文書や一時的な好みへ寄りすぎないようにする。

## 使用場面

次のような場合に使う。

- `git diff` に意味を保ったまま自然な日本語になるような書き換えが含まれている
- `sync-bilingual-docs` の実行時、改善の候補となるアイディアを検知した
- 勘ではなく、実際の修正例を根拠にしてルールを追加したい

次のような場合には使わない。

- `git diff` の中心が意味変更や事実修正である
- 日本語修正の件数が少なく、一般化しにくい
- 必要なのが日英同期だけで、スタイル改善までは求められていない

## 入力

利用できるものを組み合わせて使う。

- `git diff`
- ユーザーが指定した日本語ファイル
- `sync-bilingual-docs` から渡された修正候補
- `writing/revise-japanese-writing/` 配下の現行ファイル

## 手順

1. 変更提案を作る前に、現行の `writing/revise-japanese-writing/SKILL.md`、`SKILL-ja.md` を読む。
2. 日本語の `diff hunk` または修正候補を集める。
3. 次の判定を満たさない修正を除外する。
   - 判定
     1. 人間による修正は技術的意味を保っているか
     2. 改善の本質は、内容自体ではなく日本語の質にあるか
     3. そのルールは 1 箇所だけでなく複数ファイルで役立つか
     4. 現行スキルにその観点が未記載か、または今回の型に対して記述が弱いか
     5. スキルを肥大化させずに短く書けるか
   - 判定を満たさない修正例は次のとおり。
     - 意味そのものや事実の修正
     - 意図が混ざった構成変更
     - 再利用パターンを持たない好みの差
4. 残った修正を、次のような型で分類する。
   - 訳文調や英語追従の表現
   - 不自然な名詞連結
   - 助詞不足や述語の弱さ
   - 定着した用語とずれた語の選び方
   - 論理構成や段落運びの改善
   - 中身のない強調や AI っぽい姿勢語
5. 各内容を抽象的なルールへ還元する。
6. 現行スキルがすでにそのルールを扱っていないか確認する。
   - すでにあるなら、既存ルールの補強や明確化を優先する
   - 近いルールがあるなら、新しい章を増やさずそこへ統合する
   - 本当に新しい観点なら、その内容を追記する
   - 追記、修正時は冗長な表現とならないように注意する
7. 実行時指針を変える場合は、`SKILL.md` と `SKILL-ja.md` の両方を更新する。
8. 変更はコミットせずに残す

## 出力

最後は簡潔に報告する。

- `revise-japanese-writing` の更新が正当化されたか
- どの候補を採用し、どれを見送ったか
- どのファイルを更新したか
- 例が増えるまで保留すべき低確信度候補があるか

変更不要なら、そのことを明確に述べ、見送った理由を示す。
