# Sync Bilingual Docs

本リポジトリでは、ドキュメントの日本語版と英語版が次のような対応関係を持つ。
このスキルは、それらの日英文書を意味の揃った状態で維持することを目的とする。

- `README.md` / `README-ja.md`
- `SKILL.md` / `SKILL-ja.md`
- `references/` / `references-ja/`

## 目的

- 日英の対応文書を、意味の一致した状態に保つ
- 逐語訳ではなく、それぞれの言語として自然な文章に整える

## 対象外

- 言語間の同期を伴わない一般的な推敲
- 先に構成再設計を相談すべき大きな文書改造
- 根拠確認なしの書き方ルール抽出

日本語差分からのルール抽出や `revise-japanese-writing` の保守は、補助スキル `distill-japanese-edits` を使う。

## 入力

利用できるものを組み合わせて使う。

- ユーザーが指定したファイルまたはディレクトリ範囲
- `git diff` と `git status`
- `AGENTS.md` などのリポジトリ指示
- 英語版または日本語版の対応ファイル

ユーザーが範囲を指定していない場合は、現在の diff から対象を推定する。

## 対応関係の解決ルール

次の順で対応関係を解決する。

1. 同一ディレクトリ内のファイル対応。たとえば `README.md` / `README-ja.md`、`AGENTS.md` / `AGENTS-ja.md`、`SKILL.md` / `SKILL-ja.md`
2. ディレクトリ対応。たとえば `references/` / `references-ja/`、`maintenance/` / `maintenance-ja/`
3. `AGENTS.md` などのドキュメントに記載されているリポジトリ固有の対応ルール

対応ファイルが存在しない場合はその旨を明示し、ユーザーが求めていない限り新規ファイルを勝手に作らない。

## 手順

1. 編集前に、関係する指示ファイルと変更対象文書を読む。
2. `git diff` を確認し、変更されている日英対応ペアを列挙する。
3. 同期前に各変更を分類する。
   - 内容の追加または削除
   - 構成の組み替え
   - 用語の整理
   - 日本語の自然化または英語の表現整理
4. 変更が入っていない側を更新し、対応ペアの意味を揃える。
5. 1 文ごとの対応に縛られず、それぞれの言語として自然な文章を保つ。
6. ユーザーが明示的に改名を求めていない限り、技術要素はそのまま保つ。
   - コマンド
   - ファイルパス
   - 設定キー
   - 識別子
   - パッケージ名
   - 固有名詞
7. 日本語側に、意味を変えず自然さだけを改善した人手修正があれば、改善候補として記録する。
8. `distill-japanese-edits` は、次の節の条件を満たす場合だけ呼ぶ。
9. ユーザーが明示的に求めない限り、コミット、ステージ、公開はしない。

## `distill-japanese-edits` を呼ぶ条件

次のいずれかに当てはまる場合だけ、補助スキルを呼ぶ。

- ユーザーが `revise-japanese-writing` の改善を明示的に求めている
- `git diff` に、意味を保った日本語の自然化が繰り返し現れている
- 人間の修正から、既存指針にない再利用可能なルールが読み取れる

## 同期時の判断

### 英語側が先に変わった場合

- 変更意図を保つように日本語側を更新する
- 逐語訳よりも自然な日本語を優先する
- 新しい内容にも合うなら、ローカルで定着した用語を維持する

### 日本語側が先に変わった場合

- その変更が意味変更なのか、表現改善だけなのかを見分ける
- 意味変更なら、英語側にも内容を同期する
- 表現改善だけなら、英語側は意味を揃えつつ、修辞まで無理に対応させない

### 両側が変わっている場合

- 行単位ではなく意味で照合する
- どちらがより新しい構成や意図を持っているかを見極める
- 一方の妥当な改善を、対称性だけを理由に上書きしない

## 改善候補

日本語差分に再利用可能な改善が見える場合は、候補ごとに要約を残す。

- ファイルと節
- 修正前の傾向
- 修正後の傾向
- 意味が維持されている理由
- 暫定的な一般化ルール
- 確信度。高、中、低

これらのメモは、`distill-japanese-edits` への入力として使う。

## 確認観点

完了前に次を確認する。

- 変更された日英対応ファイルについて、対応側も確認したか
- 日本語と英語で技術的意味が一致しているか
- 技術要素を保持したか
- 日本語側が訳文調ではなく自然な文になっているか
- 表現だけの修正を、誤って意味変更にしていないか
- 改善候補には根拠が添えられているか
