# 出典

保守担当者向けに、出典の扱いを記録する。実行時の指針は `references-ja/guidance.md` に置く。

## 主な出典

Vladimir Khorikov, _Unit Testing: Principles, Practices, and Patterns_.

次の考え方を採用している。

- 実装の詳細ではなく、観測可能な振る舞いをテストする
- 単体を必ず一つのクラスと考えず、振る舞いの境界として捉える
- 共有依存と揮発性依存を制御し、可能なら安定した協力オブジェクトを実物のまま使う
- スタブを検証せず、意味のある振る舞いである場合だけ通信を検証する
- テストしにくさを設計上の問題を調べる材料として扱う
- テスト専用の調整より、プロダクションコードも改善する変更を優先する

## このスキルでの調整

- 古典学派はドメインロジックが中心のシステムで有力な既定値だが、唯一の方法とはしない。
- クリーンアーキテクチャ、レイヤードアーキテクチャ、オニオンアーキテクチャの分離は、より明確な設計がない場合の出発点であり、一貫した既存設計を書き換える根拠にはしない。
- 既存アーキテクチャを先に確認し、影響の大きな変更につながる曖昧な設計意図はユーザーと確認する。
- 明確な単体テストの依頼に必要な境界確認は専門スキルで行い、テスト全体の目的、カバレッジ方針、テストレベル間の責務分担は `guide-automated-tests` で扱う。
- ローカルの責務と制約に合わせるため、戦略を決める前にプロジェクトの状況を確認する。
- レビューでは、課題、状況、境界、ケース、実装を簡潔にたどる。

別の出典によって規則が実質的に変わる、または見直される場合に追加する。追跡だけを目的に規則 ID や実行時の指針の複製を作らない。
