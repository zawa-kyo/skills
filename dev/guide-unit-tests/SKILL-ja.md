# 単体テストガイド

## 概要

実装時とレビュー時の両方で、単体テストの作業を支援する。
目的は、テスト数やカバレッジを最大化することではない。
重要な振る舞いを、妥当な保守コストで守るテストを書くことで、コードベースを継続的に変更しやすくすることである。

このスキルは、単体テストの作成、単体テストのレビュー、ある振る舞いを単体テストで扱うべきかの判断、テストしにくさを設計フィードバックとして扱う場面で使う。

## 対象範囲

このスキルは次の用途で使う。

- 価値の高い単体テスト対象を選ぶ
- どの振る舞いを観測し、何を assert するか決める
- 出力、状態、相互作用のどれを検証するか選ぶ
- test double、stub、mock を使い分ける
- 読みやすいテスト名、setup、action、assertion を書く
- 壊れやすいテスト、過剰指定のテスト、価値の低いテストをレビューする
- 単体テストしにくいコードから設計改善の方向を見つける

結合テスト、E2E テスト、データベーステスト、CI、カバレッジツール、テストフレームワーク API の詳細設定は、このスキルの正本ではない。
単体テストの境界を説明するために必要な範囲でだけ扱う。

## 参照資料の選び方

タスクに必要な参照資料だけを読む。

| 状況                                                  | 読むファイル                               |
| ----------------------------------------------------- | ------------------------------------------ |
| 目的、品質基準、優先度、用語が必要                    | `references-ja/foundations.md`             |
| 何を単体テストにするか決めたい                        | `references-ja/test-target-selection.md`   |
| 何を assert するか、mock や stub をどう使うか決めたい | `references-ja/observation-and-oracles.md` |
| テストコードの構造を書きたい、または改善したい        | `references-ja/test-construction.md`       |
| コードが単体テストしにくく、設計問題が疑われる        | `references-ja/design-feedback.md`         |
| テストやテスタビリティのレビューを依頼された          | `references-ja/review-heuristics.md`       |
| このスキルの設計背景を確認したい                      | `references-ja/design-background.md`       |

英語で出力する場合や英語文書を編集する場合は、対応する `references/` 側のファイルを使う。
このスキルを編集するときは、`references/` と `references-ja/` の意味を同期する。

## ワークフロー

1. 依頼を、テスト作成、テストレビュー、境界選定、assertion 戦略、設計フィードバックのどれかに分類する。
2. 詳細な助言を出す前に、該当する参照ファイルを読む。
3. クラス名、メソッド名、mock、assertion を先に決めず、ユーザーが守りたい振る舞いを特定する。
4. 実装詳細に結合したテストより、外部から意味のある振る舞いを観測するテストを優先する。
5. 価値が低いテストや保守しにくいテストは、資産ではなくコード上の負債として扱う。
6. 例外があるルールでは、普遍的な規則として断定せず、適用条件とトレードオフを説明する。
7. 論点が単体テストの範囲を超える場合は、単体テストの境界と、別のテスト種別や設計作業で扱うべき範囲を明確にする。

## 出力

新規テスト作成では、次を示す。

- テストすべき振る舞い
- 推奨するテスト境界
- 優先する観測方法
- 書くべきテストケース
- テストを簡単にする設計変更

レビューでは、実質的な問題がある場合は findings から始める。
違反しているルール、リスク、最小限の有効な修正方針を含める。
blocking issue がない場合は、その旨を明確に伝え、残る文脈や検証上の不足があれば述べる。

ユーザーが別言語を明示しない限り、ユーザーの依頼言語で出力する。
