# 設計背景

## このスキルを作る理由

このスキルは、単体テストをカバレッジ向上の手段としてではなく、設計と保守の実践として扱うために作る。

単体テストは、重要な振る舞いを低い保守コストで守るときに価値を持つ。
一方で、実装詳細に密結合する、モックを過剰に使う、本番ロジックをテスト内に複製する、通常のリファクタリングを難しくする場合は害になる。

## 初期ソース

初期ソースは Vladimir Khorikov の _Unit Testing: Principles, Practices, and Patterns_ である。
この本は、テストの価値、リファクタリング耐性、観察可能な振る舞い、テストダブル、出力・状態・相互作用テストのトレードオフを整理する語彙を提供している。

ただし、このスキルは同書を唯一の正本とはしない。
他の書籍、チームの実践、言語ごとの制約、実プロジェクトから得た知見を取り込める状態に保つ。

## 設計判断

このスキルは、出典の章や特定の学派ではなく、判断レイヤーで整理する。

- `foundations.md` は、目的、品質特性、用語、優先度を扱う。
- `test-target-selection.md` は、何を単体テストにするかを扱う。
- `observation-and-oracles.md` は、何を観測し、何を正しさの根拠にするかを扱う。
- `test-construction.md` は、テストコードの形を扱う。
- `design-feedback.md` は、単体テストしにくいコードが示す設計問題を扱う。
- `review-heuristics.md` は、レビュー時に各ルールへ戻るための索引を提供する。

この構成により、新しい出典は既存ルールを補強、修正、または反証する形で取り込める。
章ごとの要約を並列に増やさない。

## 日英の参照資料

`references/` と `references-ja/` は、ファイル名と意味を同期する。
英語版と日本語版は逐語訳である必要はないが、ルール、優先度、適用条件、例外は一致させる。

`references/example.md` を追加するときは、同じ変更で `references-ja/example.md` も追加する。

## 出典管理

出典の対応、採用した論点、採用しなかった論点、保留中の疑問は `maintenance/sources.md` に記録する。
利用者向けの参照資料を、書籍の索引にしない。
